== TRACED, not unit-testable without a DOM renderer (client has no happy-dom/testing-library) ==
F1 Bell does not re-read on WS reconnect.
   useNotificationHistory.ts:151 loads once on mount; afterwards only the live frames (:157, :169) and the
   panel open (openAndMarkSeen) touch it. unread:init IS resent on reconnect (server.ts:4192) and claude
   sessions ARE refetched (useClaudeSessionState.ts:195-200), so after a phone/laptop sleep the unread is
   right and the unseen keys are not. A notification:seen missed while asleep (desktop opened the chat)
   leaves topic:<id> in the phone's keys -> bell and PWA badge +1 until the panel is opened. The code says it
   knows (NotificationHistoryButton.tsx:100 "il fronte può essersi perso una riconnessione") and only fixes it
   on open. Same for the window-local 'done'/'finished' marks: a seen frame lost while disconnected is never
   replayed, the mark stays until that subject's next turn.
F2 Archived chats banner on the session:state path but not on stream:end.
   useCompletionNotifier.tsx:757-765 loads the ARCHIVE to name a parked session's chat and then fires with no
   archived check (the only `archived` in the file is :566, the stream:end path). recordAndAnnounce refuses the
   row for an archived topic (notification-registry.ts:66), and the server push skips it (push-triggers.ts:122):
   OS banner + sound with no row in the bell. Reachable: closing a tab archives the chat and leaves its
   background work running (state/backgroundWork.ts:132-133); when that work wakes the CLI the woken turn's Stop
   moves dormant -> running -> awaiting-user.
F3 Parked-task rows are only cleared on a review exit.
   markTargetSeenAndAnnounce('task') has two callers, both on leaving 'review' (services/tasks.ts:4203, 4567);
   opening the task drawer marks nothing (client markTargetSeen is called only for terminals, paneSeen.ts:109,
   signals.ts:704). A task-parked row (push-triggers.ts:306) of a task requeued, cancelled or archived without
   passing through review counts on the bell/dock until the panel is opened. NOTIF-SEEN-01 asks the opposite;
   the 29/08 migration did it once, nothing does it at runtime.
F4 Several windows write ONE dock number from different memories (suspected).
   Every window, detached ones included (same App + TabNotificationProvider, App.tsx:361, :1399), calls
   set_app_status with its own chromeCount (useTabNotifications.tsx:203-210); lib.rs:3005 applies the last
   call. Inputs differ per window by design (done/finished marks are not raised in the window that has the
   subject in front, chatInView.ts:70). With E above, the window that had the terminal behind keeps its
   'finished' mark forever, so the dock flips between the two windows' counts on every re-render.
F5 Hook chats and terminals count differently for the same fact.
   A hook chat at awaiting-user counts on its row, its tab, the bell and the dock until its next turn or
   SessionEnd (topicAttentionCount, no seen gate by design, signals.ts:1466-1473); a hook claude-code terminal
   at awaiting-user counts nowhere (chromeAttentionSubjects reads only terminalFinishedIds, attentionTotal.ts:91;
   buildSidebarItems.ts:400). A read chat also keeps floating to the top of the sidebar (buildSidebarItems.ts:474, 733).
