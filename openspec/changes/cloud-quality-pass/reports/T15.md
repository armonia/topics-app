## Fatto

1. **`cleanupTestDataDir` rimette `DATA_DIR`** (`28470ab`, `tests/integration/helpers/index.ts`).
   `setupTestDataDir` salva il valore trovato prima del primo setup senza risposta, la cleanup lo rimette
   (o cancella la variabile). Il fix sta nella pulizia che il file che sporca chiama già, non nelle
   vittime (che sono anche sui rami aperti di T4). Scelta del «primo setup senza risposta»: se un file
   che non pulisce viene prima, la cleanup del file dopo non gli ripassa la sua cartella.
   Guardia: `tests/integration/helpers/test-data-dir-restore.test.ts`, due corse figlie con file fixture
   numerati («il file dopo trova `DATA_DIR` vuoto»), più un ratchet sui 63 file che chiamano

   `browser-state-store` che perde il suo `afterAll`) lo nomina.

## Rifiutato

- **Correggere le vittime** (`system-notices` che non pulisce `subject_attention`, `born-seen`): il brief
  vuole il fix in chi sporca, e i due file sono sui rami aperti di T4.
- **Ripristinare `DATA_DIR` dal preload, al confine fra file**: il `beforeAll` di un preload gira una volta
  per processo (misurato su 1.4.2 e 1.3.8: una riga per tre file) e il `beforeEach` arriva dopo il
  `beforeAll` del file, quindi troppo tardi per le vittime che aprono il DB nel `beforeAll`.
- **Aggiungere `cleanupTestDataDir` ai 63 file del ratchet**: forme diverse (setup in `beforeAll`, dentro
  funzioni, per test), e con la cleanup che ora rimette `DATA_DIR` la perdita si chiude alla prima cleanup
  dopo. Il ratchet impedisce che crescano.
