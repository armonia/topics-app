## ADDED Requirements

### Requirement: MT-01 — Master is an interactive claude PTY with an orchestrator system prompt

The system SHALL create the Master as an interactive `claude` PTY terminal (subscription-included, human-driven), launched with an additional `--append-system-prompt` carrying the orchestrator contract. It SHALL NOT create the Master as a chat backed by the SDK or the `claude --print` provider.

#### Scenario: Opening the Master spawns a system-prompted interactive PTY
- **GIVEN** the `claude` CLI is installed and authenticated to a Pro/Max subscription
- **WHEN** the user opens the Master
- **THEN** an interactive `claude` PTY session is created (no `--print` flag)
- **AND** its launch args include `--append-system-prompt` with the orchestrator contract
- **AND** the existing `TOPICS_AGENT_SYSTEM_PROMPT` is still appended (additive)

#### Scenario: Single global Master
- **GIVEN** an active Master terminal already exists
- **WHEN** the user opens the Master again
- **THEN** the existing Master terminal is focused/resumed
- **AND** no second Master PTY is spawned

#### Scenario: No paid engine on the Master path
- **WHEN** the Master is created
- **THEN** no request is routed through the SDK provider, the OpenClaw gateway, or `claude --print`
- **AND** model output occurs only in response to the human pressing Enter in the PTY

### Requirement: MT-02 — Proposals are scraped from the terminal buffer, not generated by an app-initiated model call

The system SHALL derive kanban proposal cards by reading the Master terminal's scrollback buffer and parsing the latest `## Next` block. It SHALL NOT initiate a model call to produce proposals.

#### Scenario: Human-triggered scrape produces cards
- **GIVEN** the user prompted the Master terminal and `claude` printed a reply containing a `## Next` block
- **WHEN** the user triggers "Aggiorna proposte"
- **THEN** the server reads the terminal buffer, strips ANSI, and extracts the latest `## Next` block
- **AND** each proposal becomes a kanban card via the existing ingest (one card per session, deduped by `claude_task_id`)
- **AND** no additional model invocation is made by the app

#### Scenario: No automatic polling of the model
- **WHEN** the Master is idle
- **THEN** the system does NOT auto-send prompts to the Master on a timer
- **AND** proposals refresh only on explicit human action

#### Scenario: Garbled or absent block degrades gracefully
- **GIVEN** the buffer has ANSI noise, wrapped lines, or no `## Next` block
- **WHEN** the scrape runs
- **THEN** ANSI is stripped and the latest valid block (if any) is parsed
- **AND** malformed rows are skipped and no error is thrown

## REMOVED Requirements

### Requirement: MASTER-01 — Master Topic creation (subscription, global) via claude-code chat provider

**Reason**: Superseded by MT-01. The `claude-code` provider uses `claude --print`, which Anthropic's 2026-06-15 billing change moves off the subscription onto a metered Agent SDK credit at API rates. The Master can only stay subscription-included as an interactive, human-driven PTY (MT-01), not as a `--print` chat.

**Migration**: Existing Master chat topics are replaced by the terminal-Master. The `## Next` parser, proposal→card mapping, and kanban cards from `refactor-master-into-kanban` are reused; only the proposal source changes from chat messages to the terminal buffer.
