## A — Security

### Applicato (quick-win innocui)
- **Timing-safe token compare** (`30484d10`): i confronti di `GATEWAY_TOKEN` in `routes/terminal.ts` e `routes/topics.ts` passavano per `===` (timing-leak teorico); ora via `timingSafeEqualStr()` (`server/utils.ts`, `crypto.timingSafeEqual` con length-guard).
- **Vite DNS-rebinding** (`30484d10`): `allowedHosts: true` accettava qualsiasi Host header; ristretto a localhost + MagicDNS Tailscale (`.ts.net`). Accesso via IP-literal Tailscale bypassa comunque il check lato Vite (documentato inline).

### Rimandato — sessione dedicata (decisione Tailscale)
- **A1 — server bind `0.0.0.0` senza default-deny auth.** Il server espone tutta la superficie `/api` file/git/memory/upload/browser-control + 3 canali WS a qualunque peer LAN/Tailscale. **Non toccato di proposito**: serve per mobile/PWA sulla LAN, e la rete è ristretta a Tailscale. Un vero fix è una dispatch-boundary default-deny (auth opt-out per-route, non opt-in), non un patch. → sessione security dedicata.
- **A2 — path-containment.** `resolveSafePath()` (l'unico resolver confinato, `utils.ts:1029`) ha zero caller; `resolveProjectPath()` (non confinato, `utils.ts:1051`) è usato ~53 volte. Traversal/SSRF sono primitive vive. Fix = far passare le rotte file/git per il resolver confinato — refactor ampio, va fatto con test di regressione dedicati. Vedi `SECURITY.md` (già dichiara local-first/no-auth/esposizione a rete non fidata fuori scope).

## B — Correttezza (bug reali chiusi)

- `autoBindProject` non era in try/catch: un throw dentro il `setTimeout` sarebbe risalito come unhandled → `chat.ts` (`dee872fc`).
- Overlay «reloading» duplicato nel terminale (doppio blocco `{reloading && !stale}`) → `SingleTerminalPane.tsx` (`dee872fc`).
- Microfono/TTS mai rilasciati se il componente voice-call smontava mid-call → cleanup su unmount in `useSpeech.ts` (`3e7cab90`).
- Fallimenti upload (inclusi `!res.ok`) silenziosi → ora raccolti e mostrati via toast in `ChatPane.tsx` (`3e7cab90`).
- Branch force-delete senza conferma esplicita; `ScriptRunner` passava `processId` dove serviva `scriptName` (stop del processo sbagliato); race su diff-fetch al cambio file; file-delete via `window.confirm` → dialog `MODAL_PANEL` (`9867fc5f`).
- `updateTopic` ritorna `Topic|null` ma il salvataggio non controllava il null (perdita silenziosa di modifiche); unlink progetto senza rollback su fallimento → `TopicSettingsModal.tsx` (`ad2ac03a`).
- Coda download browser globale (mescolava eventi tra pane) → scoped per-pane fino al layer Rust (`b17f609e`).
- `PaneTabBar` container dragover non settava `dropEffect` → su WKWebView il tab «scompariva» in pop-out-close (`4cb6a777`).

## Wave 2 — follow-up verificati (layout / state / tauri)

Tre agenti paralleli su aree disgiunte; ogni diff **ri-verificato a mano** sul codice prima del commit (i finding critici avevano precedenti falsi positivi in questo repo).

**Layout** (`201c9a6e`)
- **P0.1 — `topic:switch` non registrava il pane.** L'handler WS spingeva `toTopicId` in `openPanels` senza `ensurePaneRegistered` prima → l'orphan-id guard di `REORDER_PANES` (Effect B) lo droppava e il tab non compariva. Fix con la shape **identica** a quella canonica di `openPanel()` (`{id: topicId, type:'chat', topicId, title}`, `group:default`) — verificato leggendo `openPanel` riga 1001. Impatto stretto: morde solo quando passa la guardia `isOwnStream`.
- **P1.2 — leak pane su close.** `handleCloseProject`/`handleCloseTerminal` filtravano solo `openPanels`, lasciando l'entità in `state.panes` per sempre; peggio, un filtro nudo lascia che `REORDER_PANES` re-appenda il tab chiuso. Fix: `PURGE_ORPHAN_PANE` (nessun tombstone: project/terminale non hanno undo). Verificato che l'action esista (`types.ts:285`, test esaustivi) e che `paneId = createPaneId('project'|'terminal', …)` combaci con la registrazione.
- **P1.3 — dedup.** Estratto il segnale sintetico di reflow browser (dispatch `pane-resize-start` + 400ms `pane-resize-end`) in `notifyPaneReflow()`; entrambi i call-site migrati.

**State** (`ad7e1c3f`)
- Dedup del `backoff()` byte-identico di `tombstoneSync` + `projectLayoutSync` in `syncBackoff.ts` (il `putWithRetry` con AbortController-coalescing di `syncServer.ts` lasciato come consolidamento futuro).
- Registrato `ui-state:patch` nello schema `ws-inbound` (loose): frame letto a mano da 3 moduli, assente dal registro che l'header dice deve coprirli tutti.
- `importLegacy` idratava `closedTabs`/`gridLayout`/`projectLayout` mai letti da `HYDRATE_FROM_LEGACY` e poi cancellati → rimossi da payload + tipo.
- +3 test (durability tombstone, `paneConfig`, caso `SPLIT` del reducer). **422 pass / 0 fail.**

**Tauri** (`d44d095a`)
- Comandi self-test (`fps_report`/`focus_report`/`focus_grab_browser`/`focus_grab_window`) erano in `generate_handler!` **incondizionati** → invocabili via IPC da qualunque JS in release (scrivono stringhe del chiamante su path `/tmp` fissi; rubano il first-responder AppKit). Gated **sia la fn sia l'entry della lista** dietro `#[cfg(debug_assertions)]`. **`cargo check` verde in debug E release** (la simmetria fn+entry evita il riferimento penzolante in release).
- Rimossa dep `tauri-plugin-window-state` (mai `.plugin()`-registrata; solo commenti la citano); rimossa capability inutilizzata `shell:allow-execute` (tenuto `shell:allow-spawn`); tolto un blocco `unsafe` interno ridondante.
