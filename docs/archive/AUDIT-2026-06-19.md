## Executive summary

Topics App is a feature-rich, fast-moving desktop companion that works in practice but rests on a structurally unsafe and under-tested foundation. The single dominant risk is the security posture: the Bun server binds 0.0.0.0 (verified, server.ts:417) with no default-deny auth, and every file/git/memory/upload/browser-control/WS surface is reachable unauthenticated by any LAN/Tailscale peer. This is compounded by a systemic missing abstraction — the one containment-enforcing path resolver (resolveSafePath) has zero callers (verified), while the unconstrained resolveProjectPath is used 53 times, yielding arbitrary file read/write/delete and arbitrary in-page JS execution as live primitives. The second structural weakness is type-and-contract erosion: there is no server tsconfig and no tsc step at all (verified), ~440 `any` occurrences server-side (298 in routes alone, verified), and the WS/REST/sessionKey/marker contracts are hand-mirrored across 3-6 files that demonstrably drift (PROJECT_* markers leak into replayed model context because build-provider-history.ts strips only 3 of 5 markers — verified 0 PROJECT_ references). Third, quality is never gated: CI runs only on version-bump/tags (verified — no on:push/on:pull_request workflow), so the server is never typechecked or tested automatically, the 555-case E2E suite runs only on a developer laptop, and large blocks of it target a removed Kanban feature, are mock-fed, or contain zero assertions. Performance has real hot-path problems (broadcast-to-all fan-out with broadcastToTopic dead at 0 call sites, O(n^2) per-delta marker scans, ~965-query loadTopics N+1) but is the healthiest dimension relative to expectations. Underneath all of this is a recurring god-file pattern (topics.ts ~4000 LOC, useProjectLayout ~2159 LOC, electron main.ts ~3685 LOC) that is the structural enabler of most inconsistency and dead-code findings. Nothing here is a smoking-gun crash in normal single-user desktop use; the risk is that the safety nets a team relies on (auth boundary, type checking, CI, tests) are largely absent or dead, so regressions and exposure ship silently.

## Temi ricorrenti

### Unauthenticated 0.0.0.0 server with no path-trust boundary
The server listens on all interfaces with auth applied ad-hoc per-route (only /__daemon/* is token-gated), so the entire /api file/git/memory/upload/checkpoint/spaces/agents-spawn surface plus all three WS channels (PTY input, browser control, typing/drag) are open to any LAN/Tailscale peer. The root cause is architectural: auth is opt-in per handler instead of a default-deny dispatch boundary, and path containment is reinvented 4-5 different ways (most buggy or absent) while the only correct resolver, resolveSafePath, is dead code (verified zero callers). This turns file traversal, SSRF, and in-page page.evaluate into live primitives.

_findings: F1, F2, F14, F27, F35, F72, F102, F103, F105, F111, F119, F322, F332, F335, F349, F361, F386, F389_

### No server typecheck, no CI gate, and a dead `any` ratchet
There is no server/root tsconfig and no tsc step (verified), so ~440 server `any` occurrences (298 in routes alone, verified) and any type drift are caught by nothing. The only `any` ratchet (check:any) covers 7 hand-picked files (6 client + 1 server). CI triggers only on version-bump/tags (verified) — there is no on:push/on:pull_request workflow running tsc, unit tests, E2E, or the ratchet. The result is structural type rot at every trust boundary that no mechanism contains.

_findings: F11, F23, F47, F62, F86, F97, F110, F137, F336, F359, F368, F375_

### Hand-mirrored cross-boundary contracts that silently drift
Wire-critical contracts are duplicated across modules with no shared source and no enforcement: the WS message vocabulary lives in 3 registries (server outbound ~93, client inbound ~20, client WSMessage union) that validate only a subset and omit the highest-traffic live types (session:state, claude-event); ClaudeSessionState/phase is a 3-way manual mirror; sessionKey is parsed 3-5 incompatible ways; the invisible-marker grammar is reimplemented in 6 files where 2 server history pipelines omit PROJECT_* (verified — leaks project-binding markers back into the LLM context, contradicting the system prompt); git porcelain status is parsed positionally on the client but .trim()'d on the server (a real staged/unstaged misclassification); Topic/ChatMessage/ToolCall are byte-copied between server and client. shared/types.ts is documented as the anti-drift home but holds only provider types.

_findings: F4, F146, F154, F251, F252, F255, F268, F269, F270, F320, F321, F325, F326, F327, F330, F333, F334, F342, F346, F348, F350, F357, F363, F381_

### God-files and over-engineered multi-authority state
The heaviest modules are monolithic if-cascades / god-hooks: topics.ts (~4000 LOC, 39 endpoints + 1500-line streaming engine + STT/TTS + tunnels + dormant tasks), utils.ts (~1250 LOC AppContext factory), useProjectLayout.ts (2159 LOC, ~14 effects, forward-declared ref shims), electron main.ts (~3685 LOC), and the App root. Pane/tab open state is owned in three competing authorities bridged by ~36 effects. This structure is the direct enabler of the duplication, inconsistency, and dead-code findings (dup /project logic, full-table scans, the test that had to clone the un-extracted stream timer), and it imposes a per-request cost via the linear router waterfall.

_findings: F60, F61, F62, F171, F274, F339, F343, F345, F354, F372_

### WS broadcast-to-all fan-out and quadratic streaming hot paths
The scoped broadcaster broadcastToTopic exists but is used 0 times (verified) — every stream delta goes via broadcastToAll (100 call sites in topics.ts, verified) to every connected socket regardless of focus, so one chat fans every chunk to all tabs/windows/PWAs and triggers wasted client work. Each delta also re-scans the entire accumulated response with regex (O(n^2) per stream), and loadTopics() is a full-table 5-query N+1 (~965 queries for this user's 193 topics) called 32x server-wide, often just to fetch one topic when an indexed O(1) lookup exists. These directly threaten the documented perf budgets under multiple windows.

_findings: F25, F59, F70, F134, F345, F388, F389, F390, F391, F394, F397_

### Background timers/watchers leak with no shared disposal contract
At least 16 module-level intervals/watchers are started but gracefulShutdown tears down only ~1-2 of them; ActivityMonitor.destroy()/JournalCollector.stop() exist but are never called. Under the documented `bun --watch` dev model every reload spawns a fresh generation while old timers/fs-watchers keep firing against stale closures — duplicate log reads, duplicate persist writes, orphaned gateway fetches. The systemic root is the absence of an AppContext dispose/registry; each leak is a local nit but the pattern is uniform.

_findings: F3, F21, F29, F43, F96, F122, F362, F395_

### Removed Kanban/Master feature left a live cross-module footprint
The deleted task-board feature was never swept: ~2200 server LOC (agent-api/agent-profiles/dashboard/epoch-store on never-written tables), ~15 client components (dead AgentCard, KPI grid, AgentRoster's unusable hand-type-topic-ID flow), ~350 lines of dead client API, demo mocks, and README/BACKLOG/landing copy still advertising 'Board'/'Master'. The dormant agentApiRouter is even dispatched FIRST in the router waterfall, and topics.ts still INSERTs into the tasks table via a dead /assign branch. This is maintenance weight, attack surface, and misleading product claims, plus a 28-test E2E suite targeting selectors that no longer exist.

### E2E suite gives green-but-empty coverage despite being the stated core value
The project's declared core value is comprehensive E2E coverage, yet no CI runs it; the suite self-disables (chat-scroll/layout/grid soft-skip on missing precondition, gateway-gated live tests always skip with no gateway), contains zero-assertion and expect(true) tests, length-only mobile/layout asserts, 42 mock-fed dashboard/agent tests against dead backends, and a 28-test Kanban suite against a removed feature. The real streaming engine, security boundaries, and mobile/PWA behavior have no un-mocked coverage, and the stream-timer 'test' clones the route logic instead of exercising it. Banned waitForTimeout/networkidle patterns are taught by a stale README and used ~150-200 times; video:'on' + slowMo:300 + serial execution make runs slow.

_findings: F37, F68, F289, F290, F291, F293, F294, F295, F296, F297, F299, F354, F375, F376, F377, F378, F379, F382, F384, F385, F386_

### HTTP scheme/error-shape/body-parse inconsistency across the layer
The monorepo disagrees with itself: the server is HTTPS-by-default (certs present) but the entire CLI and one launcher hardcode http:// and are non-functional against a normal install, while only the Electron path uses https. Error responses come in three incompatible shapes ({error,details} vs json({error}) vs {ok:false,error}) that the single client parser only partly understands, mixed even within one router. Body parsing splits between safe ctx.readJSON and bare req.json() (throws 500) across ~25 sites. matchRoute exists but the largest routers hand-roll pathname=== / regex matching with different decode/trailing-slash behavior.

_findings: F58, F67, F98, F104, F106, F113, F261, F303, F304, F305, F323, F324, F328, F338, F364, F365, F367, F369, F385_

### Brittle by-accident logic: string-matching, fuzzy matches, and ignored params
Many paths work only by coincidence: endStream rewrites JSON tool-state via raw substring REPLACE; rate-limit/auth detection substring-matches free text; pricing fuzzy-matches model names bidirectionally and misses current-gen models (zero-cost tracking of opus-4-8); transitionSessionTo ignores its target param and hardcodes 'stale'; ClaudeProvider.abort ignores sessionKey and cancels every session's stream; Codex complete() forces a model rejected under ChatGPT auth; the create-new-worktree poller closes over a stale snapshot and always times out; loadActiveThread can infinite-loop on a cyclic parent_id and hang the event loop.

## Top priorità (needs-approval)

1. **Stop binding 0.0.0.0 by default and add a default-deny auth/origin boundary**  
   The single highest-leverage fix. The server is reachable LAN/Tailscale-wide with no auth on the file, git, memory, upload, checkpoint, spaces, agent-spawn, and WS (PTY/browser-control) surfaces. Binding loopback-only by default plus a shared upgrade-time + dispatch-time guard closes the entire class of remote-read/write/RCE exposure at once, instead of per-route.  
   _ids: F2, F27, F35, F57, F105, F119, F335, F361_

2. **Route every filesystem path through the existing resolveSafePath and delete the unconstrained resolver**  
   resolveSafePath already enforces containment but has zero callers (verified) while resolveProjectPath (no containment, 53 uses) and four hand-rolled prefix checks back arbitrary file read/write/delete. Making one mandatory, containment-enforcing resolver the only path-trust boundary fixes the entire scattered traversal cluster (files, memory, preview, media, openclaw-context) with one abstraction.  
   _ids: F1, F6, F14, F72, F76, F102, F103, F322, F332, F349, F386_

3. **Add a server tsconfig + tsc step and a CI gate that runs on push/PR**  
   There is no server typecheck and CI only runs on version-bump tags (both verified), so ~440 server `any`s, type drift, the dead check:any ratchet, and the entire test suite are caught by nothing on merge. A push/PR workflow running server tsc, unit tests, the ratchet, and a smoke E2E subset is the meta-fix that would have surfaced most other findings before they shipped.  
   _ids: F336, F359, F368, F375, F11, F23_

4. **Centralize the marker grammar and fix the PROJECT_* leak in the history pipelines**  
   Verified: build-provider-history.ts strips 0 PROJECT_ markers and assemble.ts's stripper omits them, so prior turns replay raw {{PROJECT_OPEN:...}} project-binding control markers back into the LLM — directly contradicting the system prompt and corrupting context. This is a real correctness/security divergence caused purely by 6-way duplication; one shared, tested marker module fixes it and prevents the next family from leaking.  
   _ids: F333, F346, F250, F69, F145, F4_

5. **Make session:state and claude-event first-class on the WS contract and unify the three registries**  
   The two highest-traffic live WS frames are absent from the server outbound registry, the client inbound registry, and the WSMessage union, so emit-time validation is hollow exactly where it matters and client/server drift is uncaught (no server tsc). These frames drive the Electron tray and client signals; a single shared/typed source + a parity test closes the busiest contract gap.  
   _ids: F146, F320, F321, F363, F381, F396_

6. **Use broadcastToTopic for stream deltas and de-quadratic the per-delta marker scan**  
   broadcastToTopic is dead (0 calls, verified) while every chunk fans out via broadcastToAll (100 calls) to all sockets, and onTextDelta re-regex-scans the whole growing response per chunk (O(n^2)). The routing data (ws.data.focusedTopicId) already exists. This directly threatens the documented 300ms cross-tab and streaming-no-reflow budgets under multiple windows and is the dominant avoidable WS/CPU load.  
   _ids: F388, F389, F70, F394, F134_

7. **Replace loadTopics() full-table N+1 on single-topic lookups with the indexed reads**  
   loadTopics() issues ~965 queries for this user's 193 topics and is called 32x server-wide, frequently on warm request paths (providerForSessionKey, /api/chat, /command) just to find one topic when getTopicBySessionKey/getTopicById are O(1) and already used elsewhere in the same file. Largest avoidable DB load on hot paths, cheap to fix.  
   _ids: F390, F25, F59_

8. **Add a shared disposal/registry so background timers and watchers tear down on shutdown/reload**  
   16+ module intervals/fs-watchers leak across the documented bun --watch dev reloads and graceful prod restarts; destroy()/stop() methods exist but are never called. Under the project's own dev workflow this compounds into duplicate log reads, duplicate persist writes, and orphaned gateway fetches. A single dispose contract on AppContext fixes the whole class.  
   _ids: F362, F395, F43, F21, F29, F122_

9. **Sweep the removed Kanban/Master feature out of code, API, dashboard, tests, and docs**  
   ~2550 LOC + 15 components + dead API + 28 E2E tests + 42 mock-fed tests + README/landing copy still describe a feature users can't reach; the dormant router is even dispatched first and topics.ts still writes the tasks table. Removing it shrinks attack surface, dispatch cost, and bundle, and stops misleading users/contributors/agents about what the product does.  
   _ids: F340, F373, F258, F71, F213, F316, F315, F376, F377_

10. **Fix the CLI/launcher http-vs-https mismatch and the Electron 127.0.0.1 cert-error gap**  
   The server is HTTPS-by-default (certs present) but the whole CLI and start-electron-only.sh hardcode http:// and are non-functional against a normal install; the Electron cert-error handler only trusts hostname 'localhost' while the app loads https://127.0.0.1, surviving today only on a fragile undocumented empty-SPKI switch. These are user-facing first-run/launch breakages, not style.  
   _ids: F303, F304, F305, F369, F276, F314_
